# Concerns

- 2026-07-22: The Java SDK returns successful responses as raw JSON to avoid a runtime JSON dependency. Consumers must parse responses themselves, and future typed responses could require a compatibility decision. Resolve through an explicitly approved public-API design before changing the response type.
- 2026-07-22: The Python, PHP, Ruby, Java, .NET, and Go releases do not yet have verified publisher or namespace ownership. A package name could become unavailable or a release could be published from the wrong identity. Resolve separately for each ecosystem by verifying the live registry name, authenticated publisher, ownership plan, and required namespace immediately before its first release.
- 2026-07-22: Packagist requires `composer.json` at the root of the package repository, but the PHP package lives under `sdks/php` in this monorepo. Submitting the monorepo directly would not produce the intended Composer package. Resolve by publishing an approved subtree split repository with `sdks/php` as its root before registering `notilify/notilify` on Packagist.
- 2026-07-22: Maven Central cannot accept `com.notilify:notilify` until the `com.notilify` namespace is verified and release credentials and a GPG signing key are configured outside the repository. Resolve by completing Central Portal namespace verification and generating publisher and signing credentials before running the release profile.
